# 康复评估过程管理系统 可行性分析报告

| 项目名称 | 康复评估过程管理系统 |
| --- | --- |
| 计划周期 | 14 周 |
| 文档版本 | V1.0 |

---

## 一、引言

### 1.1 编写目的

本报告从技术、经济、操作、法律与进度五个维度，对"康复评估过程管理系统"建设的可行性进行分析论证，为项目立项与实施提供决策依据。

### 1.2 项目背景

康复医学科评估量表种类多（FMA、Barthel、Berg、MMSE 等）、评分与分级规则复杂，传统纸质记录存在数据难追溯、算分易错、任务流转不透明等问题。本项目拟建设覆盖"评估申请 → 量表执行 → 自动算分 → 康复趋势分析"全流程的数字化管理系统。

### 1.3 主要建设内容

1. 5 类角色权限体系（管理员、科室管理员、医师、治疗师、患者）；
2. 量表引擎（题库管理、在线填表、自动算分、分级规则）；
3. 评估任务工作流（申请、执行、驳回、编辑、删除）；
4. 评估/治疗记录管理与康复趋势分析；
5. 患者自助门户与 Docker 容器化部署。

## 二、技术可行性

### 2.1 技术选型

| 层次 | 选型 | 成熟度 |
| --- | --- | --- |
| 后端 | Spring Boot 3.5 + Spring Data JPA | 企业级主流框架，社区活跃 |
| 认证授权 | Spring Security + JWT + BCrypt | 业界标准方案 |
| 数据库 | MySQL 8.0 | 开源成熟，JPA 自动建表降低运维成本 |
| 前端 | Vue 3 + Vite + Element Plus | 组件化开发效率高 |
| 可视化 | ECharts | 国内主流图表库，文档完善 |
| 部署 | Docker + Docker Compose | 三容器一键启动，环境一致 |

### 2.2 关键技术可行性论证

1. **量表引擎**：条目类型（单选/多选/数值/文本）与评分规则采用"题库 + 规则配置"方式建模，通用性强；算分由后端权威执行，保证准确性。
2. **权限体系**：采用 JWT 无状态认证 + @PreAuthorize 方法级授权，5 类角色互斥权限清晰，越权访问由后端强制拦截（前端菜单显隐仅作体验优化）。
3. **任务工作流**：评估任务状态机（待执行 → 已完成 / 已驳回）业务逻辑简单明确，执行完成后自动生成评估记录，事务保证一致性。
4. **部署方式**：三容器（MySQL / 后端 / 前端 Nginx）编排，宿主机端口映射，不依赖云平台，校园网环境即可运行。

### 2.3 技术风险

- 镜像拉取受网络环境影响：已通过配置国内镜像源与本地缓存解决。
- 医疗数据合规：评估记录删除权限仅限管理员，全量操作审计日志，满足实训环境要求。

**结论：技术可行。**

## 三、经济可行性

### 3.1 成本分析

| 项目 | 内容 | 费用 |
| --- | --- | --- |
| 硬件 | 个人笔记本（8GB+ 内存，Docker Desktop） | 已有，0 元 |
| 软件 | 全部采用开源技术栈（JDK/Node/MySQL/Vue/Spring Boot） | 免费 |
| 部署 | 本机 Docker 部署 | 免费 |
| 人力 | 单人开发 14 周 | 实训/课程投入 |

### 3.2 效益分析

1. **直接效益（上线后）**：评估记录电子化，减少纸质台账；自动算分杜绝人工计算错误；任务流转全程可追溯。
2. **教学效益**：完整覆盖软件工程全流程（需求→设计→开发→测试→部署），锻炼全栈开发与容器化部署能力。
3. **复用价值**：量表引擎与权限框架为通用设计，可复用于其他医疗信息化项目。

**结论：投入几乎为零，经济可行。**

## 四、操作可行性

1. **面向用户**：界面采用 Element Plus 组件规范，操作路径短（如任务执行在弹窗内完成量表填写并实时预览得分）；患者端只保留三个菜单（我的床位、评估记录、治疗记录），无学习门槛。
2. **面向管理员**：账号一键初始化（5 个默认账号），量表题库种子 SQL 导入即可使用，JPA 自动建表无需手工导结构。
3. **面向运维**：`docker compose up -d` 一条命令启动全部服务；数据持久化在 Docker volume，重启不丢失。
4. **培训成本**：角色划分清晰，各角色仅见本职菜单，培训成本低。

**结论：操作可行。**

## 五、法律可行性

1. 全部采用开源框架与组件，均遵循宽松开源协议（Apache 2.0 / MIT），无商业授权风险；
2. 系统内测试数据为演示数据，不涉及真实患者隐私信息；
3. 系统内置角色权限与审计日志，符合医疗信息系统"最小授权、全程留痕"的基本合规要求；
4. 本项目仅用于教学实训，不对外提供医疗服务，不涉及医疗器械注册等法规约束。

**结论：法律可行。**
