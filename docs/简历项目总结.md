## 三、简历项目描述（精选版，约 3–5 行）

**康复评估过程管理系统（个人全栈项目）**　2026.09

- 独立完成前后端开发：Spring Boot 3.5 + Vue 3 + MySQL，实现 **5 类角色（管理员/科室管理员/医师/治疗师/患者）的 RBAC 权限体系**，JWT 认证 + 方法级授权 + AOP 操作审计日志，前端菜单按角色动态显隐；
- 设计并实现**量表引擎**：题库化建模 8 种常用康复量表（73 条目 / 172 选项），支持单选/多选/数值/文本四类题型，**后端权威自动算分 + 分级规则判定**，前端实时预览；
- 实现**评估任务工作流**（申请 → 执行/驳回/编辑/删除 → 自动生成评估记录），事务保证数据一致；康复趋势分析基于 ECharts 可视化；
- 面向患者实现**自助门户**：床位查询、本人评估/治疗记录只读查看，接口按患者身份强制过滤；
- 完成 **Docker 容器化部署**（MySQL / 后端 / 前端三容器编排），一键启动。

## 六、面试追问准备

1. **为什么算分要放后端？** 防止前端篡改分数，保证医疗数据可信；前端实时预览仅作体验。
2. **权限怎么防越权？** Spring Security 方法级 @PreAuthorize；即使前端隐藏菜单，接口层也会拦截；统一异常处理器返回 403。
3. **JWT 无状态认证怎么处理退出/失效？** 前端存储 token，请求头携带；失效返回 401 前端跳登录。
4. **评估任务删除已完成任务会怎样？** 事务内连带删除其生成的评估记录，保证数据一致性。
5. **数据库为什么用 JPA 自动建表？** 开发阶段迭代快；上线时可切换 validate 模式配合人工脚本。
6. **Docker 部署的细节？** 三容器 compose 编排，MySQL healthcheck 保证启动顺序，后端镜像打包时拷入本地 jar，Nginx 反代 /api。
7. **遇到的最大难点？** 量表引擎的通用化建模（条目类型 + 规则化评分）与权限模型设计；部署阶段国内网络镜像拉取问题（镜像源配置）。
