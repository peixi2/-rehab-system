## 一、项目概述

### 1.1 项目背景

康复医学科日常业务中，评估量表种类多、评分规则复杂，评估与治疗过程依靠纸质记录，存在以下痛点：数据分散难追溯、评分易出错、评估任务流转不透明、患者无法及时了解自身治疗情况。本项目旨在建设一套面向康复科的数字化管理系统，覆盖从评估申请、量表执行、自动算分到康复趋势分析的全过程。

### 1.2 项目目标

1. 实现 5 类角色（系统管理员、科室管理员、康复医师、康复治疗师、患者）的权限管理体系；
2. 实现量表引擎：题库管理、在线填表、自动算分、分级规则判定；
3. 实现评估任务工作流：医师申请 → 治疗师执行 → 自动生成评估记录，支持驳回、编辑、删除；
4. 实现康复趋势分析与病人自助门户；
5. 完成 Docker 容器化部署，一键启动。

### 1.3 项目范围

**范围内：**

- 用户与权限模块（JWT 认证、角色授权、操作审计日志）
- 基础数据管理（病人、医生、床位、治疗项目、账号）
- 量表库与量表引擎（8 种常用康复量表，73 条目 / 172 选项）
- 评估任务工作流（申请、执行、驳回、编辑、删除）
- 评估记录 / 治疗记录管理
- 康复趋势分析（ECharts 可视化）
- 患者门户（床位查询、本人评估与治疗记录只读查看）

**范围外：** 医保结算、HIS/LIS 系统对接、移动端 App。

## 五、风险管理

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 量表评分规则理解偏差 | 算分结果错误 | 第 2 周与指导老师逐条确认评分与分级规则；后端权威算分，前端仅预览 |
| 权限越权漏洞 | 数据泄露 | 后端 @PreAuthorize 强制校验；测试阶段专项越权用例 |
| 医疗数据合规 | 数据误删 | 评估记录删除仅限管理员；全量操作审计日志 |
| 开发环境网络问题（镜像拉取失败） | 进度延误 | 配置国内镜像源；基础镜像本地缓存 |
| 单人项目时间冲突 | 延期 | 每周进度检查点；非核心功能（趋势图）可延后 |

## 六、质量保证

1. 编码规范：前后端统一命名与目录结构，关键逻辑注释；
2. 代码审查：每阶段结束自查 + 指导老师抽查；
3. 测试要求：核心流程（申请→执行→记录→趋势）必须有全流程用例；权限模块必须覆盖 5 角色的越权用例；
4. 数据一致性：算分结果以服务端为准，前端实时预览仅作提示；
5. 版本管理：每日代码提交，里程碑节点存档。

## 七、进度跟踪机制

- 每周复盘：对照第 4 节周计划检查完成情况；
- 里程碑评审：M1–M5 五个节点强制检查，未达标不进入下一阶段；
- 风险升级：连续两周进度滞后 20% 以上，需调整范围（如裁剪非核心功能）。
